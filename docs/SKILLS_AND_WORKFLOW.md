# Skills, агенты и рабочий процесс

## Использовано при проектировании

- `skill-installer` — проверен актуальный каталог устанавливаемых skills;
- `Spreadsheets` — требования к будущему Excel-файлу: формулы, структурированные данные, графики, рендер и визуальная QA-проверка;
- три параллельных агента — продуктовые практики, техническая архитектура и требования RuStore;
- официальные источники RuStore, Capacitor, Workbox, WebKit, Android, CFPB, MoneyHelper, W3C, MDN и Microsoft.

## Skills, которые уже подходят проекту

| Skill | Когда использовать |

| `Spreadsheets` | Создание, расчёт, графики и визуальная проверка `.xlsx` |
| `visualize` | Интерактивная проверка метрик, порогов и вариантов дашборда |

| `computer-use` | Проверка реального поведения Excel, Safari/Home Screen, Android Studio и RuStore Console в GUI |
| `imagegen` | Черновые иллюстрации и варианты store-asset после выбора бренда |

## Рекомендуемые skills на следующих этапах

В curated-каталоге найдены, но пока не установлены:

- `security-threat-model` — перед добавлением аккаунтов, синхронизации или платежей;
- `security-best-practices` — при hardening мобильного приложения и backend;
- `sentry` — только если будет выбран Sentry и законный контур его размещения;
- `playwright` — автоматические browser-сценарии, offline-проверки и визуальная регрессия PWA; установить перед реализацией `apps/web-pwa`.

Опционально можно подключить Figma-плагин на этапе дизайн-системы. Сейчас его установка не нужна: сначала проверяются терминология и сценарии в Excel.

## Рабочий процесс

1. Изменение правила сначала фиксируется в документации.
2. Для правила добавляется или обновляется golden fixture.
3. Формула проверяется в Excel.
4. Та же семантика реализуется в чистом TypeScript `packages/domain`.
5. Автоматические тесты сравнивают результат с fixture.
6. Один React UI проверяется в Safari/Home Screen и Android/Capacitor, включая airplane mode.
7. IndexedDB migration и versioned backup/restore проходят round-trip.
8. Перед релизом обновляются PWA/RuStore checklists, privacy-декларация и журнал решений.

## Правило доказательства готовности

«Сделано» означает не только наличие файла или кода, но и:

- воспроизводимый контрольный пример;
- автоматическую проверку формул/логики;
- визуальную проверку ключевых экранов/листов;
- отсутствие ошибок импорта, экспорта и миграций;
- актуальную документацию и release checklist.
